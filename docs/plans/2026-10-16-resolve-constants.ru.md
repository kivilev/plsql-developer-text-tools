# План фичи: «SQL без констант» (Resolve Constants)

Дата: 2026-10-16. Статус: этап 1 сделан (ветка `feat/copy-sql-with-constants`): команда SQL Tools → Copy SQL with
constants resolved — константы из того же окна (блоки, тело пакета, спецификации в том же тексте, `pkg.c_x`,
`owner.pkg.c_x`), переменные/параметры → бинды, удаление INTO / RETURNING INTO, защита колонок (`SET col =`,
список колонок INSERT). Ядро готово к спецификациям из БД (`ISpecSource`), в плагине не подключено (этап 2).
Прогон по корпусу 15 004 файла / 82 080 запросов: 0 падений. Шаг 0 (проверки в IDE) не выполнен.

**Решение 2026-10-16 (пользователь): плагин автономный.** Никаких SQLcl, Java, Docker и внешних клиентов — только код
в DLL. База — только через уже открытое соединение IDE (колбэки `SQL_Execute`/`SQL_Eof`/`SQL_Next`/`SQL_Field`).
Порядок резолва константы:
1. текст окна (блоки, тело пакета, спецификации в том же тексте);
2. подключена база → спецификация пакета из `ALL_SOURCE` (текущая схема → приватный синоним → публичный);
3. значение так и не найдено → бинд с именем константы: `pkg.c_x` → `:c_x` (при конфликте имён `:pkg_c_x`).
Без базы `x.y` считается константой пакета, если `x` — не таблица/алиас запроса, не запись цикла, не `seq.nextval`
и не вызов `f(...)`. Функции пакета без скобок (`info.getday`) без базы тоже станут биндом; с базой — остаются.
Этапы «Evaluate in DB» (`begin :v := pkg.c; end;`) и автоперехват Ctrl+C — не делаем.

## Проблема

В пакете/процедуре SQL ссылается на константы: локальные (`c_active constant varchar2(1) := 'A';`),
глобальные из спецификации/тела своего пакета, из чужого пакета (`pkg_const.c_max_rows`, `hr.pkg_const.c_x`).
Скопировал запрос в SQL Window или нажал Explain Plan — `ORA-00904: invalid identifier` /
`PLS-00221 ... is not a procedure or is undefined`: SQL не видит PL/SQL-констант. Сейчас разработчик руками
ищет каждую константу и подставляет значение.

## Что делает плагин (поведение для пользователя)

Выделил запрос (или просто поставил курсор внутрь него) в Program / SQL / Test Window → команда:

| Команда | Результат |
|---|---|
| **Copy SQL with Constants** | в буфер обмена кладётся запрос, где константы заменены значениями |
| **Open in SQL Window** | то же, но сразу открывается новое SQL Window с готовым запросом |
| **Explain Plan with Constants** | открывается Explain Plan Window с готовым запросом |

Пример:

```sql
-- было (в теле пакета)
select * from orders o
 where o.status = c_status_new
   and o.type_id = pkg_const.c_type_retail
   and rownum <= gc_max_rows;

-- в буфере
select * from orders o
 where o.status = 'NEW' /*c_status_new*/
   and o.type_id = 10 /*pkg_const.c_type_retail*/
   and rownum <= 1000 /*gc_max_rows*/;
```

Где доступны команды: меню Plug-Ins → Text Tools → **SQL Tools**, контекстное меню редактора
(`IDE_CreatePopupItem` для `PROGRAMWINDOW`, `SQLWINDOW`, `TESTWINDOW`), кнопка на ленте. Горячая клавиша —
штатно через Preferences → Key Configuration (пункты меню плагина туда попадают сами).

В статус-баре — итог: «Replaced 3 constants; unresolved: l_date (variable)».

## Почему не «автоматически на Ctrl+C»

В API плагинов нет события копирования. Перехват возможен только через Windows clipboard listener
(`AddClipboardFormatListener`) — это подмена чужого буфера обмена в фоне, ломает правило «не портить текст
пользователя» и непредсказуемо (копировали код, а вставилось другое). Поэтому MVP — явная команда + хоткей
(например `Ctrl+Shift+C`). Автоперехват — возможный опциональный режим потом, по умолчанию выключен.

## Как определяем запрос

1. Есть выделение → берём его.
2. Нет выделения → берём SQL-оператор под курсором: от `SELECT|WITH|INSERT|UPDATE|DELETE|MERGE` до `;`
   с учётом скобок, строк и комментариев.
3. Чистка для запуска отдельно (опции, по умолчанию вкл.): убрать `INTO ...` / `BULK COLLECT INTO ...` из
   `SELECT INTO`, хвостовой `;` для Explain Plan, `RETURNING ... INTO`.

## Как находим значение константы (порядок поиска = область видимости PL/SQL)

Только лексер, без полного парсера PL/SQL: токены (идентификаторы, строки `'..'`/`q'[..]'`, комментарии,
числа) + распознавание деклараций `имя CONSTANT тип [NOT NULL] {:= | DEFAULT} выражение ;`.

1. **Тот же текст (окно)** — `IDE_GetText`: декларации в блоках, охватывающих выделение, изнутри наружу:
   вложенная процедура → внешняя → глобальные тела пакета. Имя, перекрытое переменной/параметром ближе к
   запросу, — не константа, не трогаем.
2. **Спецификация своего пакета** (открыто тело пакета) — исходник спецификации.
3. **Квалифицированные `pkg.c_x`, `owner.pkg.c_x`** — исходник спецификации `pkg`.
   Синонимы: `pkg` может быть синонимом → резолв через `ALL_SYNONYMS`.

Откуда брать исходник объекта: `IDE_GetObjectSource(type, owner, name)` (кэш IDE), фолбэк —
`ALL_SOURCE` через `SQL_Execute` в сессии плагина (`SQL_UsePlugInSession`, чтобы не мешать основной).
Кэш исходников в памяти плагина на время одной команды (без инвалидации-проблем).

### Значение = выражение

| Вид | Что подставляем |
|---|---|
| литерал: `'A'`, `10`, `-1.5`, `q'[x]'`, `date '2020-01-01'`, `null` | как есть |
| ссылка на другую константу (`c_b := c_a \|\| '_X'`) | рекурсивно раскрываем, защита от циклов, глубина ≤ 10 |
| SQL-совместимое выражение (`to_date('...','...')`, `power(2,10)`, `sysdate`) | выражение в скобках как есть |
| PL/SQL-only (`boolean`, вызов PL/SQL-функции, `%type` записи, коллекции) | не трогаем, в «unresolved» |

Опция «Evaluate in DB» (по умолчанию выкл.): нерешённые константы публичной спецификации вычисляются через
`begin :v := <pkg.c_x>; end;` (`SQL_SetVariable`/`SQL_GetVariable`). Выкл. по умолчанию, потому что обращение
к пакету запускает его секцию инициализации (побочные эффекты) и требует коннекта.

Литерал из вычисленного значения строится по типу из декларации: `varchar2/char` → `'..'` с удвоением
кавычек, `number/integer/pls_integer` → число с точкой (NLS-независимо), `date` → `to_date('…','yyyy-mm-dd hh24:mi:ss')`,
`timestamp` → `timestamp '…'`.

## Опции (Preferences плагина, ini рядом с DLL или `IDE_PlugInSetting`)

- Комментарий с именем константы после значения (`10 /*pkg_const.c_type_retail*/`) — вкл.
- Переменные и параметры → бинды `:p_id` (SQL Window сам спросит значения) — вкл.
  Поля записи `l_rec.id` → `:l_rec_id`.
- Убирать `INTO` — вкл.
- Evaluate in DB — выкл.

## Архитектура (по каркасу Text Tools)

```
src/TextTools.Core/Sql/
  PlsqlLexer.cs           токены: идентификаторы, строки (вкл. q'..'), числа, комментарии
  StatementLocator.cs     запрос под курсором / в выделении, чистка INTO
  ConstantScanner.cs      декларации CONSTANT + области видимости (блоки, вложенные процедуры)
  ConstantResolver.cs     поиск по цепочке областей, рекурсия, циклы; источник исходников — интерфейс
  ISourceProvider.cs      GetPackageSpec(owner, name) -> string? ; в тестах — фейк
  Substituter.cs          замена токенов + комментарии + бинды; итог-отчёт (replaced/unresolved)
src/TextTools.Plugin/
  IdeSourceProvider.cs    IDE_GetObjectSource → ALL_SOURCE, ALL_SYNONYMS
  Clipboard.cs            CF_UNICODETEXT через user32 (OpenClipboard/SetClipboardData)
  Menu.cs                 новая группа SQL Tools + popup-пункты
```

Ядро — чистая функция `Resolve(windowText, selection/cursor, ISourceProvider, options) -> (sql, report)`;
всё тестируется без IDE. Новые колбэки (`IDE_CreateWindow` 20, `IDE_GetObjectSource` 79,
`IDE_CreatePopupItem` 69, `IDE_GetWindowObject` 110, `SQL_UsePlugInSession` 50, `SQL_SetVariable`/`GetVariable`
54/55) — сверить индексы с `PlugInIntf.pas` (правило репо).

Правила безопасности те же: текст в редакторе не меняем вообще (результат — в буфер или новое окно), любая
ошибка → статус-бар, SQL только когда окно не выполняется, лимиты на размер текста и глубину рекурсии.

## Шаг 0: штатный Explain Plan (F5), проверено в PL/SQL Developer 14, 2026-10-17

- F5 на выделенном запросе в Program Window сам заменяет PL/SQL-переменные и константы на бинды (`:Var1`), значений
  констант не подставляет.
- Баг IDE (не плагина — подтверждено отключением плагина): при кириллице в тексте выше по запросу (комментарий
  `-- расчётный счёт*`) замена съезжает на число кириллических символов — похоже на байтовые смещения в UTF-8:
  `AND t.state = c_active_state` → `AN:D :Var1 = c_active_state`. Обход — наша команда Copy SQL + вставка в окно плана.
- Вывод: команда «Explain Plan with constants» (`IDE_CreateWindow(wtPlan, text)`) имеет смысл — даёт значения констант
  и не ломается на кириллице.
